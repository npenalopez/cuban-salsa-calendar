New, as approved

  • Festival pages with dates, status, Get passes, calendar, Instagram, website, details, full line-up, about, map, other editions, correction link, and an Event JSON-LD preview.
  • Get passes uses ticketUrl. No record has one yet, so the prototype falls back to the website, labelled as such. Turn that off in Tweaks ("demoTicketLinks").
  • Submit a festival and Suggest a correction, with inline validation, an error summary, and a success state. The Turnstile spam check is a placeholder.
  • Filters: When (next 30 days, next 3 months, pick dates), Where, saved only, sort. Archive and Dates TBA views.
  • Saved without an account: share the list as a link (the person who opens it gets "Save all"), and add all to calendar.
  • Calendar feeds per region and for your saved list. In the prototype, "Copy link" shows the future webcal:// address and ".ics" downloads the file.
  • Status: postponed, cancelled, sold out; "last checked" when set. Share via the phone's share sheet, or copy the link. Dark mode: Auto, Light or Dark.

Known gaps, to close in the production build

  • The prototype uses #/ routes. Production pre-renders real paths (/festivals/{id}/, /2026/11/) with the JSON-LD and OG tags in the HTML. That's the actual SEO fix.
  • Sheets close on Esc and on a tap outside, but don't fully trap focus yet. Use a proper dialog primitive in production.
  • Flags load from flagcdn.com, and the map is an OpenStreetMap embed. In production, bundle the flag SVGs and use a static map image for speed.
  • Submit and correction forms need a Cloudflare Pages Function and a real Turnstile key to send anything.
  • Pull UI strings into a dictionary so a second language can be added later.
